# v0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish v0.3.0 from the merged Go refactor with current quick-start defaults, version-contract coverage, Linux archives, checksums, and multi-platform GHCR images.

**Architecture:** Prepare a narrow version-only change on top of the refactor merge, prove the release Compose contract before and after the change, and merge it through the ordinary protected-branch workflow. Then create one immutable annotated tag and let the existing release workflow build, signpost, and publish every release artifact from that tag.

**Tech Stack:** Go 1.25, Docker Compose, Git, GitHub Actions, GitHub CLI, GHCR

**Spec:** `.github/workflows/release.yml` and `docs/superpowers/plans/2026-08-30-release-0.2.0.md`

## Global Constraints

- The stable tag is exactly `v0.3.0` and resolves to a commit reachable from `main`.
- Only current defaults and quick starts move to `0.3.0`; historical v0.1.0 and v0.2.0 evidence remains unchanged.
- The public API, configuration schema, and Admin UX do not change.
- The published release contains exactly the Linux amd64 archive, Linux arm64 archive, and `SHA256SUMS`.
- GHCR publishes `0.3.0`, `0.3`, `0`, and `latest`, each with linux/amd64 and linux/arm64 manifests.
