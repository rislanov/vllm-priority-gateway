# v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish v0.2.0 from the gateway decision telemetry merge with current quick-start defaults, version-contract coverage, Linux archives, checksums, and multi-platform GHCR images.

**Architecture:** Keep version selection in the existing release boundary: checked-in deployment examples advertise the current stable version, while `.github/workflows/release.yml` derives build metadata and image aliases exclusively from the immutable annotated tag. Prepare the version update through a reviewed commit on `main`, tag that exact commit, then use the repository's resumable manual release workflow and verify every published artifact.

**Tech Stack:** Go 1.27, Docker Compose, Git, GitHub Actions, GitHub Releases, GHCR

**Spec:** `.github/workflows/release.yml` and `README.md#ci-and-releases`

## Global Constraints

- The stable tag is exactly `v0.2.0` and must resolve to a commit reachable from `main`.
- The release workflow must remain the sole publisher of archives, `SHA256SUMS`, GitHub Release state, and GHCR aliases.
- Historical v0.1.0 validation evidence remains unchanged; only current quick-start defaults move to 0.2.0.
- The local GPU/vLLM observability stack remains running and is not recreated or destroyed by release preparation.
