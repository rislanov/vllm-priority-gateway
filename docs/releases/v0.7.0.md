# v0.7.0

## Request-size admission and token reservations

- Enable request-size admission per model pool for Chat Completions, Completions, and Responses. Input and output caps can be configured by pool, priority class, and client. The feature is off by default.
- Enabled pools estimate input size and reserve tokens for outstanding requests against pool and client budgets. Reservations are allocated with the inference lease and released on completion or expiry. Valid actual usage feeds the existing soft TPM limits.
- High and Critical retain emergency admission during recoverable PostgreSQL coordination outages, using replica-local token budgets and independent tokenizer limits.
- Admin shows the effective limits after saving. Metrics and request events expose estimation, reservation, and rejection data.

The README now leads with the gateway's use case and deployment model.

## Upgrading

PostgreSQL migration 000007 adds request-size policy and reservation accounting. The coordination contract moves from version 3 to 4. Drain ingress and stop all old replicas before starting the upgraded group, then verify coordination and inference readiness before restoring traffic. Before enabling request-size admission on a pool, qualify the estimation profile against every serving backend and drain legacy requests from that pool.

See the [PostgreSQL rollout guide](https://github.com/rislanov/vllm-priority-gateway/blob/v0.7.0/docs/postgresql-production.md#request-size-admission) for upgrade and rollback steps and the [operations guide](https://github.com/rislanov/vllm-priority-gateway/blob/v0.7.0/docs/operations.md#request-size-admission) for configuration and monitoring.
