# v0.6.2

## Deployment-time coordination reset

PostgreSQL deployments can now set `LLMGW_COORDINATION_RESET_ON_START=true` to
remove incompatible replica registrations during startup, avoiding the wait for
stopped replicas' heartbeat TTL. The toggle defaults to `false` and works
independently of the deployment system.

Reset and registration happen in one transaction. Matching new replicas are
preserved, including concurrent starts. Leases, rate state, circuits, replay
receipts, configuration, API keys, and analytics remain intact. Heartbeat and
recovery continue checking compatibility after startup.

## Upgrade procedure

1. Stop ingress, drain active requests and streams, and stop every old gateway
   connected to the database. Prevent old processes from restarting.
2. Deploy v0.6.2 replicas with identical coordination settings and
   `LLMGW_COORDINATION_RESET_ON_START=true` in their process environment.
3. Verify `/coordination-readyz` on each replica and inference readiness before
   restoring traffic.
4. Set the toggle back to `false` for subsequent starts. Existing containers must
   be recreated to receive an updated environment; editing `.env` alone or a plain
   container restart does not replace their environment.

This is not a mixed-version rolling-upgrade mode. The toggle does not stop old
processes or clear residual leases. Enabling it with SQLite is rejected. No new
schema migration is introduced in v0.6.2; migrations from intervening releases
still apply when upgrading an older deployment.

See the [full deployment and troubleshooting guide](../postgresql-production.md#reset-old-replica-registrations-during-deployment).
