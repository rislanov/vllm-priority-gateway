# v0.6.3

## Automatic coordination upgrades

PostgreSQL gateways now wait for incompatible replica registrations to expire or
be removed by their owners, instead of immediately failing startup. Configure
`LLMGW_COORDINATION_STARTUP_WAIT_TIMEOUT` (default `3m`, `0` for fail-fast).
Only initial compatibility conflicts retry; cancellation interrupts waiting and
database errors still fail startup. Runtime compatibility checks remain enforced.

Graceful shutdown removes the process's own registration after HTTP draining and
lease cleanup, before closing PostgreSQL. Crashes or failed cleanup rely on the
existing heartbeat TTL. Waiting never deletes another replica's registration.

## Deployment

Use these defaults for an ordered stop-all/start-all upgrade:

```text
LLMGW_COORDINATION_STARTUP_WAIT_TIMEOUT=3m
LLMGW_COORDINATION_RESET_ON_START=false
```

Kubernetes can automate the sequence with `Recreate` when one Deployment owns all
gateway replicas connected to the database. Configure a startup probe to allow
the compatibility wait before liveness checks, and allow sufficient shutdown and
rollout time. The HTTP listener opens only after registration succeeds.

This approach permits downtime and does not enable incompatible rolling updates.
Before returning traffic, verify coordination readiness on every new replica and
inference readiness. v0.6.2 does not unregister at shutdown; when upgrading with a
changed fingerprint, allow for its remaining heartbeat TTL. Choose a startup wait
longer than the largest old TTL plus margin. Compatible fingerprints do not need
to wait for old registrations.

The force-reset toggle remains an emergency option, default off. No schema
migration is added in this release; earlier migrations still apply if needed.
See the [deployment guide](../postgresql-production.md#automatic-coordination-upgrades)
for Kubernetes probes, grace periods, and failure handling.

## Validation

PR #51 passed all seven CI checks, including race detection, browser tests, builds,
unit tests, and Go vet. Local PostgreSQL 17 tests cover waiting, cancellation,
graceful unregister, bounded cleanup, and runtime compatibility enforcement.
An intermittent SQLSTATE 40001 in the existing concurrent reset recovery-barrier
test was also reproduced on pre-change main; its retry policy is unchanged.
